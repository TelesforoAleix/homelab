## Facts learned, for the ADR and the standards

- **sudo-rs matches arguments exactly.** A lone trailing `*` is the only wildcard; any other
  wildcard in an argument is a parse error. The grant is therefore a list; a new unit or config
  file is a new line. ADR-049 §2's glob table is amended to name things. The C-sudo hazard (`*`
  matches a space) is recorded in the guide for the day this node runs C sudo.
- **sudo-rs's refusal text** is *"I'm sorry <user>. I'm afraid I can't do that"*; `sudo -n -l <cmd>`
  works and exits 1 on refusal, which is how destructive denies are tested without running them.
- **`sudo -l` display:** a lone `*` argument is not shown; a `*` after an argument is.
- **`sshd -T` prints `allowusers` one line per name.**
- **Landing a sudoers file is lockout-class and the rollback needs a root shell already open** —
  now a row in `safe-changes-headless.md` (`acf0f74`). Not exercised: the gate stopped the bad file
  before it landed, which is the better outcome.
- **The verifier's "newest backup" is lexical** (`sort | tail -1`), so a suffixed same-day
  directory wins over the bare date: give it the path. And a same-day backup is renamed, never
  `--force`d.
- **Two owner-side slips, both on the MacBook:** the alias `HostName` left at `CHANGE-ME`, and
  trailing `# comments` on pasted lines executed by zsh. The runbook now sets the hostname with
  `sed` from the `homelab` alias and carries no trailing comments.
