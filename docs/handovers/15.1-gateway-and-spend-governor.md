## 1. Purpose

Everything on the node that answers with a model today does it through two subscription CLIs,
capped by count, costing nothing marginal. This phase adds the first provider that **costs money per
call** — Vercel AI Gateway, chosen in ADR-033 — and, in the same phase and the same commit series,
the **spend governor** without which ADR-033 §5 forbids any metered call: four windows, attended
and unattended budgets in money, checked before the call, persisted, failing closed.

It is the first phase where a mistake costs money rather than time, and the last one before 23.1
needs a cheap model to decompose with. Its deliverable is small and exact: a `gateway` provider
behind the 15.0 registry, a `utility` route that reaches it, a governor that provably refuses, and
a ledger the owner can reconcile against the gateway's own dashboard to the cent.

**Not built here, by decision:** routing proper (Phase 15 — the strategy's §15 policy is *not*
implemented; routes remain a static table); the cache-prefix discipline (23.2 — but the governor
*records* cache read/write tokens from day one so 23.2 has data); embeddings, reranking,
transcription (Phase 10 / 17); any SDK (ADR-033 §2 — the Vercel agent prompt for Node.js and the
AI SDK **does not apply** to this node: no Node, no npm, `urllib` and `ssl` only); evaluation
suites (strategy §16 — later, on the ledger this phase produces); a model call for classification
(23.1's, on the route this phase creates).

## 3. Learning objectives

- What a spend governor is *for* — the combination "metered + system-initiated" — and why
  "check before, fail closed, persist" are each necessary rather than nice.
- Reading a gateway response's usage block and turning it into money with a price table, and why
  unknown price must mean *refuse*, not *estimate*.
- The difference between the gateway's own budget (a backstop that stops at $10 after the fact)
  and ours (a control that refuses before).
- Why a provider that costs money gets an `unattended` decision of its own, and what the
  unattended budget in money should be relative to the attended one.
- How much a "cheap" model call actually costs on this workload, measured, not read from a table.

## 4. Functional objectives

1. **`GatewayProvider`** in `providers.py`: plain `urllib`/`ssl`, key from `$CREDENTIALS_DIRECTORY`,
   model id from the registry, bounded request (question + context, the same two things the CLIs
   get — nothing more leaves), timeout from config, usage parsed from the response; refuses to
   construct without a readable credential.
2. **The spend governor** in a new `spend.py`: ceilings in money for **hour, day, week, month**,
   **attended and unattended separately**, checked and reserved **before** the call at the model's
   *maximum possible* cost for the request (input tokens estimated from length × price, output at
   `max_output_tokens` × price), settled to the actual cost from the usage block after; persisted in
   `/var/lib/homelab-model-helper/spend.json` under `flock`; **fails closed** — an unreadable or
   unparsable ledger, a model with no price entry, or a usage block missing from the response each
   refuse or, post-call, settle at the reserved maximum and log a warning.
3. **The registry** gains the provider entry 15.0 shaped: `metered: true`, `credential:
   gateway-key`, `models` with `id`, `price` (`input`, `output`, `cache_read`, `cache_write` per
   million), `max_output_tokens`, `reasoning` where the model takes it. The presence refusal is
   removed **in the same commit** as the governor. A metered model without a full price entry
   fails config load.
4. **Routes:** `utility` → `gateway/luna` (for 23.1); `owner-interactive` and `execution-agent`
   **unchanged** (subscriptions first — the owner's `/ask` does not start costing money because
   this phase exists). One more route only if §6.3 says so.
5. **The reservation debt closed:** a provider returning `exhausted` (or any pre-call refusal)
   releases its count reservation; the governor's money reservation is released the same way.
6. **A ledger the owner can reconcile:** every metered call writes one line (ts, request id from
   the caller if given, route, model, usage tokens by kind, reserved, settled, window totals after)
   — no content; `/status` (or a new `/spend`) shows the four windows for both budgets; the
   gateway dashboard's number matches the ledger's for the phase, stated to the cent.
7. **Nothing regresses:** `/ask` unchanged and free; 15.0 fixture 19/19 (extended); the endpoint's
   `execution-agent` route unchanged; helper score ≤ 3.8 after `LoadCredential=`.

## 6. Decisions still open

Recommendations are the orchestrator's; overturn with an OBSERVED reason.

**6.1 Where the money check sits relative to the count check.** Recommendation: order is shape →
route → eligibility → **count reservation → money reservation** → call → settle both. Money after
count so a count refusal (free) is never preceded by a money reservation that then needs release.
Both released on any pre-call refusal (objective 5). One `flock` per file; the two files are
independent (a subscription provider never touches `spend.json`).

**6.2 The ceilings.** Recommendation, in USD, well under the gateway's $10/week:

| window | attended | unattended |
|---|---|---|
| hour | 0.25 | 0.10 |
| day | 1.00 | 0.40 |
| week | 4.00 | 1.50 |
| month | 8.00 | 3.00 |

Attended + unattended weekly = 5.50 < 10. Configuration, tunable by the owner; the numbers are
recorded with the reasoning ("a Luna call costs well under a cent; a runaway loop at these
ceilings stops inside an hour for under 35 cents"). The phase itself spends **≤ $1.00** (§14).

**6.3 Which models and routes beyond `utility`.** Recommendation: **`utility` only** as a route
that anything reaches. Register **two** models under `gateway` — `luna` (`openai/gpt-5.6-luna`,
reasoning none, `max_output_tokens: 1024`) and `sol` (`openai/gpt-5.6-sol`, high) — so the
registry proves it can hold more than one and a second price entry is validated, but route only
`utility`. No DeepSeek/Gemini/GLM in this phase: they are the strategy's *provisional* choices and
each is a vendor added to the egress list (§6.5); Phase 15 proper adds them with an evaluation. If
23.1 turns out to need a second route, it adds it.

**6.4 `unattended` on the gateway provider.** Recommendation: **`true`**, because the whole reason
for the unattended budget in money is that 23.1's decomposition and later scheduled work will be
unattended and need the cheap model. The unattended ceilings above are the control; the gateway's
$10 is the backstop. Recorded in the guide as the decision that makes ADR-033 §5's "metered +
system-initiated" combination live, and why it is safe.

**6.5 The approved-provider list (ADR-039 §4), made explicit — owner signs.** Recommendation: a
`providers_approved` list in `config.json` — `["anthropic-cli", "openai-cli", "vercel-ai-gateway:openai"]`
— where the gateway entry names the **serving provider behind the gateway**, not just the gateway:
data goes Vercel → OpenAI for `openai/*` models. A model whose vendor prefix is not on the list
fails config load, and every gateway request pins `providerOptions.gateway.only` to that derived
vendor. This per-request pin is the git-owned enforcement point. A team-wide dashboard allowlist is
not required or relied on because it lives outside git and can drift; if the owner sets one anyway,
the guide records it as belt-and-braces with its OBSERVED date. **OBSERVED 2026-09-13:** Vercel says
the default is dynamic provider selection and documents `providerOptions.gateway.only` as the hard
request-level allowlist: https://vercel.com/docs/ai-gateway/models-and-providers/provider-options.
The owner pastes one line approving the list; the guide records it verbatim. Adding `deepseek/*`
later is one list entry and an owner line, which is what ADR-039 §1 promises ("tightens in exactly
one place").

**6.6 Pricing source and drift.** Recommendation: prices are typed into `config.json` by hand from
the gateway's model page, with a `price_observed: 2026-09-DD` field per model; the settle step logs
a **warning** if the gateway's response carries a cost field that differs from ours by > 10 % (if
it carries one — S1 finds out); the guide says prices drift and the ledger reconciliation (row 12)
is how drift is caught. No automatic price fetch — a fetch that fails or lies is worse than a
stale number the owner reconciles weekly.

**6.7 Seal the key with `systemd-creds`?** Recommendation: **no** in this phase. It is revocable in
one click, the TPM dependency adds a failure mode to a component 23.1 will depend on, and the bot
token's seal already proves the mechanism if it is ever wanted. Row in ADR-046 says "not sealed,
by decision; revoke at …".

**6.8 What `/status` shows.** Recommendation: add a `/spend` command to the bot (owner-only,
privileged allowlist not required — it reads, never acts) printing the eight figures and the
week's ledger count; `/status` unchanged. The bot reads `spend.json` **through the helper** (`op:
spend`), not from the file — `homelab-bot` has no path into `/var/lib/homelab-model-helper` and
gets none.

**6.9 Timeouts on a metered route.** Recommendation: `timeout_seconds: 60` for the gateway (Luna
answers in seconds; a 120 s hang is money at risk), and a rule in the config comment and the
guide: **a route's summed provider timeouts + 30 ≤ `RuntimeMaxSec`** (270). `utility` is one
provider; fine.

**6.10 The first real call.** Recommendation: it is **row 10**, run by the owner from Telegram via
a temporary `/ask` variant? **No** — `/ask` stays on subscriptions. The first real call is through
the **endpoint** with `role: utility` from a stub client in the runbook (the 23.0 fixture's client),
so the whole pipe — harness → helper → gateway — is what is proved, and the ledger line has a
request id. Question: something with a known short answer. Cost expected: fractions of a cent.

## 9. Security considerations

- **This is the first credential on the node that spends money.** Blast radius: whoever holds it
  can spend up to the gateway's $10/week backstop until revoked — one click. It lives under
  `LoadCredential=` as the bot token does; `aleix` can read it interactively (admin); no service
  account can. ADR-046 row 7.
- **The governor is the only thing between unattended work and the backstop.** Fail closed is
  tested by breaking the ledger (row 4), not by reading the code. A governor that estimates when it
  cannot read is a governor that spends.
- **Reserve at maximum, settle at actual** — the alternative (reserve at estimate) can overshoot a
  window by one call's worth. State the overshoot bound: at most one call's `max_output_tokens`
  worth per window, and only if the reservation logic has a bug — the reservation *is* the bound.
- **Nothing new leaves.** Row 8: the request body is the same two strings the CLIs get. Assembled
  context is 23.2's and needs ADR-039 in full; this phase widens the *destination* (a new vendor via
  a processor), which is why §6.5's list is owner-signed.
- **The key never touches a command line, a script's stdin, an environment variable, a journal
  line, `git`, or the chat.** The runbook opens an editor for it. The owner's password manager is
  the only other copy. Row 16 and row 20 check.
- **Price drift is a security concern**, not only a budget one: a model that gets 10× dearer with
  the same config would pass the governor 10 calls before the day ceiling notices. §6.6's warning
  and weekly reconciliation are the control; the gateway's backstop is the last line.
- **`/spend` reads, never acts.** No allowlist promotion.
- **User-space only** — no sshd, firewall, Tailscale, boot or volume change.
