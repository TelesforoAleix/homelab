## What the next phases inherit

### Phase 23.1 — decomposition — by name

1. **The `utility` route:** `["gateway/luna"]` → `openai/gpt-5.6-luna`, `reasoning: "none"`,
   `max_output_tokens: 1024`, `timeout_seconds: 60`. Prices per million: input `$0.20`, output
   `$1.20`, cache read `$0.02`, cache write `$0.25` (`price_observed: 2026-09-13`).
2. **Measured cost and latency of one call, from the ledger:** `$0.0000104` (22 in / 5 out) and
   `$0.0000318` (21 in / 13 out + 10 reasoning — Luna reasons even at `none`; billed as output).
   1.9–2.2 s through the endpoint. The **reservation** per call is ~`$0.0013` (input bound +
   1024 output tokens at the dearer rate) — that, not the settled figure, is what a window must
   have room for.
3. **A classification call is unattended by definition** and must send `"unattended": true`; it
   draws on the unattended budget (`$0.10/$0.40/$1.50/$3.00`), which at ~$0.0013 reserved admits
   ~75 calls an hour and ~300 a day — and is what the owner's `/spend` shows first when a scheduler
   misbehaves. The attended budget is never touched by it (row 3).
4. **Adding a route:** a key in `routes` naming ordered `provider/model` pairs; the caller sends it
   as `role` (`^[a-z0-9][a-z0-9-]{0,31}$`); nothing else selects. Install via the agent's staging
   path; no restart beyond the socket.
5. `X-Homelab-Client` is 32 characters at most — an endpoint `bad_request`, learned the hard way.

### Phase 15 — routing proper — by name

1. **The registry as it stands:** two gateway models (`luna` routed, `sol` registered with pinned
   OpenAI rates, unrouted); two subscription providers unchanged. `providers_approved =
   ["anthropic-cli", "openai-cli", "vercel-ai-gateway:openai"]`, owner-signed. **Each new vendor
   is a new approved entry**, owner-signed, and a `providerOptions.gateway.only` pin the helper
   derives from the model id — the strategy's §14 list is not configured; nothing beyond OpenAI-
   served models can be routed until its line is signed.
2. **Ledger fields for evaluation:** `route`, `provider`, `model`, `budget`, `usage` (four token
   classes), `reserved_usd`, `settled_usd`, `status`, `settle_note`, `request_id` (joins the
   endpoint audit line and the helper journal), `window_totals_after`. No latency field — the
   journal's `took=` is the only timing; add one if routing wants it.
3. **The reserve/settle overshoot bound, measured:** one reservation, `$0.001305550`–`$0.001310300`
   per call at 1024 output tokens; the settled figures were 0.8 % and 2.4 % of the reservation.
   Cross-route fallback by price is still refused (15.0); it is this phase's decision with these
   numbers.
4. **Debt, by name — the 400 mapping.** A deleted key is answered with HTTP 400
   `invalid_request_error`, not 401; the helper settles an unclassified non-2xx at the reserved
   maximum. Decision at S3 close: keep fail-closed. *Map `invalid_request_error` with a known
   pre-inference `code` to a release, once the gateway's error codes are catalogued from
   observation.* The catalogue so far: 403 (no credit, `type`/`code` unread at the time),
   400 `invalid_request_error` (deleted key, no `code` field journaled).
5. **Debt — price drift.** Prices are manual with `price_observed`; the helper warns when the
   gateway's `usage.cost` differs from the local figure by > 10 %. Weekly reconciliation
   (guide) is the control. Nothing fetches prices.

### Phase 23.3 — governance — by name

1. **The ledger schema** is above and in the guide; a budget as harness machinery would attach
   at `SpendGovernor.reserve()` — the one function that says no — with `route`, `budget` and
   `request_id` already on every record.
2. **The governor is per-node, not per-client or per-agent.** The endpoint's calls and the bot's
   share one pair of budgets; `client` is a declared label at the endpoint and does not reach
   the ledger. Per-client budgets are a schema change here and an identity decision there.
3. **Fail-closed lines are budget state, not billing.** Two exist (`$0.002615850` together).
   Anything that reports spend to a person or a policy must show the dashboard figure with the
   fail-closed total beside it, as `costs.md` does.

### Phase 14 — backup — by name

1. `/etc/homelab-model-helper/gateway-key` **is in the archive** (secret material, by design — the
   archive is already secret material). `verify-node-backup.sh` lists it as critical.
2. `/var/lib/homelab-model-helper/spend.json` is state whose loss **resets every window to zero**.
   A restore should note the time and, if within a month of the backup, accept that the restored
   windows are fuller than reality (the safe direction) or emptier (if calls happened after the
   backup — the unsafe one; the gateway's $10/week is the floor under that).
3. `credential.conf` under `homelab-model-helper@.service.d/` is the third file; in the archive.
4. **Run the close backup from the phase's worktree until it is merged.** 15.1's first close
   archive came from `main`'s script and lacked the helper's `credential.conf`; the verifier with
   no argument also picks the lexically newest directory (a two-stage-old one). Re-run from the
   branch with the path given → PASS. Two same-day-directory lessons in one phase: rename, never
   `--force`, and name the archive to the verifier.
5. Left on the node at close, by design: nothing from this phase — the S3 `.bak` files, the
   revoked key's `.bak` and the staging files are removed in the close (see the closing report).
