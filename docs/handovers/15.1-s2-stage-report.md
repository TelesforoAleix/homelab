## HTTP 403 finding

- **OBSERVED:** Vercel's official API documentation classifies HTTP 403 as "Insufficient
  permissions"; it distinguishes HTTP 401 as invalid or missing authentication, HTTP 404 as an
  absent model or endpoint, and HTTP 429 as rate limiting. Source: [OpenResponses API error
  handling](https://vercel.com/docs/ai-gateway/sdks-and-apis/openresponses#error-handling), read
  2026-09-13.
- **OBSERVED:** Vercel documents a structured error body containing `message`, `type`, `param`, and
  `code`, but the current helper deliberately surfaces only the HTTP status and does not log an
  upstream free-text body that could echo request content. The historical attempt therefore does
  not establish the gateway's more specific error code.
- **OBSERVED:** Vercel routing rules can deny a request with HTTP 403. Source: [AI Gateway routing
  rules](https://vercel.com/changelog/ai-gateway-routing-rules), read 2026-09-13.
- **OBSERVED:** the dashboard evidence rules out a configured provider/model routing rule as the
  source of this 403.
- **PREDICTED:** the remaining cause is a permission refusal after gateway authentication and
  routing, but the evidence does not distinguish an account entitlement, model/provider access, or
  another permission layer. None is recorded as the root cause.
- **PREDICTED:** another real attempt is unsafe until the orchestrator authorizes a specific
  diagnostic or correction and retry.
