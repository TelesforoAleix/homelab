## What exists now

`homelab-agent` (uid 994) on the node: `/bin/bash`, no password, its own group and no other, one
`authorized_keys` line, reached from the MacBook by `~/.ssh/id_ed25519_homelab_agent` through
`ssh homelab-agent` (BatchMode, ConnectTimeout 10, no tty, no agent). `/etc/sudoers.d/homelab-agent`
(`root:root 0440`, committed as `config/sudoers.d/homelab-agent`) — a `NOPASSWD` **list**: seven
named `homelab-*` units × nine `systemctl` verbs, the read set, two config files by name, two
ledgers by name, `data-volume.sh status`; every lockout-class binary, the volume's lock, and every
credential file denied by full path. `sshd`: `AllowUsers aleix homelab-agent`. Backup: both new
paths; the private key never on the node. All sixteen rows OBSERVED; row 12 by the executor.

## To Phase 15.1, by name

- **Alias:** `ssh homelab-agent`. **Staging:** `/tmp/homelab-agent/` (cleared at boot; the agent
  `mkdir -p`s it per session). **The two file names are fixed by the grant:**
  `/tmp/homelab-agent/model-helper-config.json` → `/etc/homelab-model-helper/config.json` and
  `/tmp/homelab-agent/harness-config.json` → `/etc/homelab-harness/config.json`, via
  `sudo -n install -m 644 -o root -g root <src> <dst>` — **644**, not the brief's 600.
- **Ledgers:** `sudo -n cp -p /var/lib/homelab-model-helper/spend.json …/spend.json.bak` and
  `sudo -n mv …/spend.json.bak …/spend.json`; same for `calls.json`. `cp -p` keeps `aleix` as
  owner — this is the §8 ledger-restore defect fixed. No other names are allowed.
- **Units the agent may restart:** `homelab-telegram-bot.service`, `homelab-model-helper.socket`,
  `homelab-harness.service`, `homelab-workbench.service`, `homelab-watchdog.timer/.service`,
  `homelab-data.target`. **Full unit name, one per call** — `homelab-harness` without `.service`
  is refused.
- **Rewrite the S3 runbook in AGENT/OWNER form before it runs.** OWNER keeps: the credential
  editor (`gateway-key`), the Vercel dashboard, Telegram, and `aleix`'s `sudo` where a path is not
  on the list. Everything else is AGENT, run and read by the executor.
- **The money path stands:** the agent can replace the helper's `config.json`; the gateway's
  per-key budget is the backstop. Say so in 15.1's handover.

## To every later phase — the convention, one paragraph

A runbook has two blocks. **AGENT**: run by the executor over `ssh homelab-agent`; it captures and
reads its own output and reports it OBSERVED; the default for every step. **OWNER**: a password, a
credential paste, a browser, a phone, or a lockout-class change; the executor says "your turn" and
stops. The executor never asks the owner to run something the AGENT block could, and never asks
for a password. A step the grant does not cover is either an OWNER step or a new line in
`config/sudoers.d/homelab-agent` — `visudo`'d on the node, committed, `sudo -l` re-pasted into
the guide. sudo-rs matches arguments exactly, so "a new line" means the exact command.

## To Phase 14

Two new paths in the backup and the verifier's critical list: `/etc/sudoers.d/homelab-agent`,
`/home/homelab-agent/.ssh/authorized_keys`. Excluded by nature, and the verifier fails if present:
`home/homelab-agent/.ssh/id_ed25519_homelab_agent`. A restore gets the account and the grant back
from the archive (`useradd` is not replayed — the restore runbook must create the account with
uid 994 / gid 979 first or accept renumbering) and the owner re-runs the sshd `AllowUsers` step.
Two verifier quirks recorded in the S2 report: "newest" is lexical, and same-day backups are
renamed, never `--force`d.

## ADR-049 §2 amendments (for the acceptance commit)

1. The table's globs (`homelab-*`, `/etc/homelab-*/*.json`, `/tmp/homelab-*/*`, `cp`/`mv` within a
   directory) become named entries — sudo-rs allows no wildcard inside an argument (OBSERVED:
   `visudo` refusal at S2 step 1).
2. `install -m 600` → `-m 644` (the helper runs as `aleix`, the harness as `homelab-harness`).
3. `cp` → `cp -p` with fixed `.bak` names.
4. "an explicit `!` line before the allow" → *after*; sudoers is last-match-wins.
5. The "matching deny" for argument globbing is moot under exact matching; the C-sudo hazard is
   recorded in the guide, not in the file.

## Open risks

- The config-replace money path (stated; bounded by the gateway budget).
- PREDICTED: the root-pager `LESSSECURE` behaviour — the alias never allocates a tty.
- The grant is a list: a unit added by a later phase without a line here is simply not
  operable by the agent until the line is added. That is a feature, and a step to remember.
