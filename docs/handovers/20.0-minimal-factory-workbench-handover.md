## 1. Read this first

**The adapter interface is unproved.** It has exactly one implementation — the deterministic fake.
ADR-036's validation item and the brief's §8.1.3 both require the same project to run on a *second*
adapter without its records changing, and that check **has not been run**, because no second adapter
exists. An interface with one implementation is a guess about what the second one will need.

The brief predicted this would be the phase's likely unevidenced claim (§16.2). It is being stated
plainly rather than skipped. **Phase 23 inherits the risk** and is the phase that will discover
whether the abstraction is real, since it builds the first real backend.

## 2. What was decided, and where

**ADR-036** resolved the brief's §6.1 at a checkpoint before any code was written. The owner chose
**CLI engine + local `127.0.0.1` server**, overruling the assistant's CLI-only recommendation, to get
a writable interface now rather than a viewer beside a terminal.

Three things flow from that and are now load-bearing:

1. **The CLI is the engine; the server is a surface.** Adding or removing a surface changes no write
   semantics, which is what keeps the rejected CLI-only option available as a fallback.
2. **The server parses; the browser does not.** One parser, one validator.
3. **Python**, stdlib where possible, PyYAML as the single dependency.

## 3. What exists

```text
surfaces (cli.py, server.py)  ->  engine.py  ->  records.py  ->  ops/ + git
```

1,900 lines across `workbench/`, plus the acceptance project, the tests, and a Workbench mode for the
existing dashboard. Modules: `records` (the only parser), `schema`, `engine`, `approvals`, `audit`,
`identity`, `agents`, `budget`, `gitops`, `project`, `ids`, `errors`, `adapters/`.

**The dashboard is no longer read-only.** It was 864 lines of working viewer; it was kept and
extended rather than rebuilt, which was the right call — it already rendered every record type.

## 5. Problems, failures and reversals

**A `git reset --hard` deleted an approval record.** A project keeps `ops/` in the same repository as
its product. Switching the main checkout to a feature branch took the live `ops/` with it, and the
hard reset destroyed records written since the last commit. Fixed with a **disposable worktree**: the
main checkout never leaves `main`. The accepted steps said *"feature branch or disposable worktree"*
from the start; the reason only became legible after the records were gone.

**`git rev-parse --abbrev-ref HEAD` fails on an unborn branch** — the standard incantation does not
work in the one state every new project passes through. `git branch --show-current` does.

**Three dashboard bugs were invisible from the code.** Action buttons rendered as empty boxes
(`button { color: #ffffff }` plus a white background — the labels were in the DOM the whole time);
the action block appended a duplicate on every click; and three labels still said "read-only" while
the page offered write buttons. **The third is the one that mattered**: those labels are how a person
decides whether an action is safe.

**The brief's own §2 was wrong in both directions**, corrected by the owner mid-phase: it treated the
existing dashboard as a finished artifact to inherit, and it posed §6.1 as a new question when
Factory's `roadmap.md`, `open-questions.md` and `paperclip-style-management-interface.md` had already
framed it. Reading Factory's design documents was made step 1 of the implementation scope as a
result.

## 6. What the next phase must not silently inherit

1. **The adapter interface is unproved** (§1). Do not treat its shape as settled.
2. **`design/project-workspace-layout.md` contradicts ADR-028** — it calls a project's `agents/` a
   *"synced copy"* where ADR-028 requires a reference. Workbench implements the **reference**. The
   document is pre-ADR and needs correcting in **Phase 20**; it would otherwise propagate into every
   project Workbench creates.
3. **`roadmap.md` V1.6 is marked "planned" and is built.** Verify Factory's labels rather than
   trusting them.
4. **`parseLooseYaml` still exists in `dashboard.js`** for the `file://` fallback path. It is lossy.
   It is out of the write path, and it is **not labelled as lossy in the UI** — a partial parse that
   renders as though complete. Either label it or delete it.
5. **Approval expiry defaults to 7 days**, chosen because the design review left it undecided. It is
   a placeholder, not a decision.
6. **Review-round limiting is implemented in the acceptance harness, not the engine.** The default of
   two rounds is proved, but a project-configurable limit is not yet an engine concern.
7. **No `ops/` schema migration path exists.** Records carry `template_version: "0.1"` and nothing
   reads it yet.

## 7. What Phase 23 inherits

The adapter interface in `workbench/adapters/__init__.py` is the seam Phase 23 builds against:
`Request` carries agent role, a bounded task summary, instructions, context, capabilities, and
non-authoritative hints. It deliberately carries **no** model, provider, key, temperature or system
prompt — a test asserts those field names are absent, because ADR-035 §4's "same shape of adapter"
claim dies the moment one leaks through.

`Budget` already implements the two limits and keeps unknown cost unknown. ADR-033's spend governor
is still a precondition for any metered call, and **this phase made none**.

## 11. Security

No credential is held, read or written. `grep` over `workbench/` finds no secret; a completed run
produces none in its logs. The server binds loopback only, verified with `lsof`, and refuses any
other host. `gh` is ambient authority and is **not exercised** in the default path. The synthetic
project is public and synthetic, containing no owner data and no token-shaped string.

ADR-025's locks are **unchanged**: no model output is dispatched, because no real model was called.
ADR-034 §13's change takes effect in Phase 23, not here.

The node was not touched. ADR-032's content gate was not engaged.
